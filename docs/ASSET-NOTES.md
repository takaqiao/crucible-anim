# 素材侦察记录

**这些记录来自 `tools/contact-sheet.sh` 抽帧后的实际读图（逐帧 alpha 采样 + 正确解 alpha 的联系表），
不是从文件名或目录结构推断出来的。** 文件名会骗人：`ImpactDark` 是亮红色的、
`GroundBurn` 前一半是满屏火球、`markers.chain.standard.loop.dark_black` 这条路径压根不存在。
备注列才是本文件真正的价值——它记录的是只有看图才能发现的坑：空帧头尾、素材自带的命中闪爆、
真正可循环的帧区间、分支之间帧数不一致、以及某些分支在暗色地图上完全隐形。

**兵库规则改选素材时，必须先在这里补上对应记录。**
`test/asset-notes.test.mjs` 会校验表格里每条路径都能无降级解析，并且五个视觉槽位
（cast / travel / impact / aftermath / persist）都有选材。没有记录就直接写进规则表，
等于回到了「按文件名猜」的老路。

几条贯穿全表的通用结论：

- **画幅尺寸不统一**：JB2A 多为 400x400，eskie 多为 800x800，blfx 多为 1200x1200。
  同一个 `.scale()` 值在三家之间差 2-3 倍，混排时应改用 `.size()` 定尺寸。
- **帧率不统一，且表里没有帧率列**：71 条视觉记录里 38 条（54%）不是整 30fps——
  30fps=33 条、24fps=24 条、29.97fps(30000/1001)=12 条、25fps=1 条、60fps=1 条。
  24fps 的不止 `jb2a.liquid.splash` 与 eskie.casting / eskie.attack，还有整个
  `jb2a.markers.*` / `magic_signs.*` / `energy_field.*` 家族（persist 槽 17 条里就占 9 条）；
  eskie 也不是一律 30fps，eskie.damage / buff / pulse / burn 实测都是 29.97；
  `eskie.poison.01` 是全表唯一的 60fps。**一律按 frames/30 换算，24fps 素材会短算 20%、
  60fps 素材会长算一倍**——逐条帧率与分支差异见文末「同族分支的帧数与帧率不一致」。
- **空尾很常见**：大量素材末尾有 10-20 帧纯空帧，`waitUntilFinished` 会白等半秒到一秒。
  表中标注了各自建议的 `endTime`。
- **自带闪爆的素材不能再叠闪光层**：这是一个独立的表列「自带闪爆」——93 行里 29 行标「是」
  （cast 9 / travel 4 / impact 15 / aftermath 1；persist 与 sound 全为「否」），
  也就是说 impact 槽 22 条视觉记录里有 15 条素材内部已经带了一次爆发帧。判定口径是
  **素材自己某几帧出现的高亮爆发**（白闪 / 星芒爆闪 / 亮核爆出 / 自带命中光环），
  不是「这条素材被当闪光用」这种语义描述。凡标「是」的，S3 再叠通用 impact 闪光层就是双闪，
  两者必须二选一——同族里往往有现成的无起手闪版本可换（例如 `jb2a.impact.011.*` → `jb2a.impact.012.*`）。
  边界判定留档：`jb2a.shield.02.outro_explode`（结尾是碎裂而不是白闪）、`jb2a.teleport.01`（白色拖影亮带）、
  `eskie.pulse.energy.01`（同心冲击环，帧 0 即有环但无亮核爆发）三条按此口径判为「否」。
- **联系表工具丢 alpha 的问题已修复**：旧版 `tools/contact-sheet.sh` 用 ffmpeg 默认解码器抽帧，
  丢掉了 VP8/VP9 的 alpha 平面，部分素材（`jb2a.shield.02.*`、`jb2a.liquid.splash.*`、
  `jb2a.markers.skull.dark_red.*`、`jb2a.impact.ground_crack.still_frame.*`）在旧联系表里
  呈现为实心色块或满屏噪点，`jb2a.cast_generic.01.blue` 更是被解成「白底蓝漩涡」（边框平均
  亮度 244/255）。现在脚本按 codec 自动选 `libvpx` / `libvpx-vp9` 解出 alpha，再合成到
  0x303030 深灰底、输出不带 alpha 通道的 rgb24 PNG——透明区必定精确等于底色，任何偏离
  底色的像素都是素材真的画上去的。
- **本表第一轮侦察是在工具修复前完成的，观感型断言要区别对待**：可量化的那半（帧数、
  空头/空尾区间、相位分界、峰值帧位置、alpha 峰值数字、色支枚举、`_template` 锚点数组）
  大体可信；「被画幅切平 / 实心色块盖死 token / 某段整体变暗 / 某半幅是空的」这类观感型
  断言错得最多。工具修好后已把 **71 条视觉记录全部重验完**（第一轮抽验 11 行、第二轮全量
  重验其余 62 行），订正过的行在备注里标了【订正】，汇总见文末「本轮订正与待复核」。
- **⚠ 早期版本受抽帧工具的 alpha 缺陷影响，未重验的行不能直接信**：这份清单最初是用不解
  VP8/VP9 alpha 平面的 `contact-sheet.sh` 写的，看到的画面与游戏里的真实外观不符，
  于是浓淡、覆盖、裁切、明暗、空间分布这一类断言成片失真。**凡未带【订正】标记、
  又不在两轮重验范围内的行——即 `sound` 槽那 22 行——其结论未经正确解码复核**，
  引用前请自己按修好的工具/频谱重看一遍。
- **联系表上的黄色数字是贴片序号，不是源帧号**：`drawtext` 画在 `select` 之后，标签只会
  从 0 数到 N-1。源帧号 = 贴片号 × step（step 由 stdout 的 `frames=N step=S` 给出）。
  照着黄字直接写帧号会整体差一个 step 倍数。

- **`sound` 槽的「帧数」列是毫秒时长**，不是画面帧——psfx 是 .ogg 音频，没有帧的概念。
  这些行的相位结构与坑点来自频谱图与包络分析，判读方式和视觉槽不同，但同样是实测而非猜测。
- **同一条路径可以出现两次**：`jb2a.markers.fear.dark_purple.01` 与 `jb2a.markers.skull.purple.01`
  在 aftermath 与 persist 两个槽各占一行，因为同一素材在两个槽里的用法与坑点不一样
  （一次性余波要自己补 fadeIn/fadeOut，长期挂载则直接循环）。

第一轮抽验总结出三类，第二轮 48 行订正把它们坐实并补了两类。括号里是第二轮 48 行中命中该类的
大致行数（一行常同时命中多类）：

1. **「被画幅切平 / 裁出直边」**（第一轮 2 行全伪；第二轮几乎每行都顺手复核过四条边，无一行
   真的被切）—— 丢 alpha 的近白底渲染里，柔光外扩会看起来像被方形画幅切平。
   判据：`bbox` 滤镜 + 四条边的 alpha 最大值。
2. **「浓 / 淡 / 亮 / 暗 / 密度」判反或夸大**（约 19 行，最高频）—— 「几乎看不见的淡红残雾」
   实为均值 104 的近黑污渍、「偏暗紫看不出打了什么」实为高饱和亮品红且盖脸、「整体偏亮最抢戏」
   实为全场最稀薄。根因是丢 alpha 后半透明粒子被渲成实心块、缩图又把稀疏亮点和透明底平均成灰。
   判据：中心区/环带 alpha 均值与分位、alpha≥128 的像素占比、合成到多种底色后的亮度差。
3. **空间分布判反**（约 20 行）—— 「中心有亮核」实为中心最空、「缺口固定在右侧」实为缺口绕圈、
   「粒子从下缘生成」实为 72-88% 高度、「环紧贴画幅边缘」实为缩进 20px 才有内容。
   判据：分环带/分横带/分象限的 alpha 均值曲线，别信单帧观感。
4. **帧号与相位边界**（约 20 行）—— 空帧区间差一帧、峰值帧差一帧、整段帧号偏 3-6 帧。大半源于
   拿联系表贴片序号 × step 倒推源帧号（见前言）。判据：逐帧 alpha 均值/峰值表，别数贴片。
5. **把衰减默认成单调**（约 12 行）—— 实测普遍是反弹、脉冲或多峰：收拢到底后朝外抛一圈、
   「余烬」尾巴其实还会闪三下大亮弧、循环素材是每 10-20 帧一次的周期脉冲。
   直接后果是 `endTime` 被切在闪烁中间或砍掉真正的爆发。判据：完整的逐帧 alpha 均值序列。
6. **同族关系想当然**（约 11 行）—— 「和某某是同一素材换色」（实为另一次渲染，alpha PSNR 只有
   21-26 dB）、「唯一变体」（实为 10 个色支，说的是另一条路径）、「四个变体可互换」（实为 5 个
   且其中一个离群）、同名分支帧数不等长。判据：alpha 平面逐帧 PSNR + `colorsUnder` + 逐分支 ffprobe。
